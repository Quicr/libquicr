Detailed Description

Client-session callbacks copied when the client is added.

All callbacks are optional. They may run synchronously on an API caller thread, including while session locks are held, or on a transport notification thread. Callbacks may be concurrent across objects or transports. Return promptly. Callback arguments other than the session handle and user_data are borrowed only for the call. Do not re-enter manager, session, or handler operations on the same objects unless a specific API explicitly permits it. Never destroy a callback-owning object from its callback. The application must keep user_data valid until session_removed or manager destruction. Reply callbacks must return a fully initialized ACCEPT or REJECT reply; the library copies borrowed reply data.

Examples
simple_publish/main.c, and simple_subscribe/main.c.
