Detailed Description

Callback interface for session events common to both client and server mode.

Callbacks that answer an inbound request return a Reply, which carries either the response or a reason code for rejecting it. The session sends the protocol message from that reply and correlates it with the request itself, so there is nothing further for the application to call and no request identifier for it to keep.

Return a value to accept, or an Unexpected<Error<E>> holding a reason code, optional reason string, and optional redirect to reject. A Reply<void, E> accepts by returning {}.

An answer that cannot be given straight away is deferred with Reply::Defer(). Its producer is called on the session's message-handling thread and must start, rather than perform, slow work there. When that work completes, invoking the supplied completion callback marshals the response back to the transport notification thread.

Callbacks are invoked on the transport notify thread, which also carries stream and connection events, so an immediate reply must return promptly; anything slow belongs in a deferred one. Each reply is answered exactly once. The transport catches exceptions that escape the producer while it is invoked or the continuation after it is queued; either case can leave the request unanswered until the peer times it out. Exceptions on an application-created worker thread remain the application's responsibility.

A callback that is not overridden keeps its default, given per method below.

virtual void quicr::Session::Callbacks::MetricsSampled ( const std::shared_ptr< Session > &  session,
const ConnectionMetrics &  metrics 
)
virtual

Notification callback to provide sampled connection metrics.

Invoked every Config::metrics_sample_ms in either client or server mode. The period based metrics reset after this callback, so a value not read here is lost. Per track metrics for the same period follow this call, via PublishTrackHandler::MetricsSampled and SubscribeTrackHandler::MetricsSampled, sharing the same last_sample_time.

Invoked on the transport notify thread, which also carries stream and connection events. Return promptly; a slow implementation backs the queue up and other notifications are dropped to make room.

Parameters
sessionThe session the metrics belong to
metricsCopy of the connection metrics for the sample period
